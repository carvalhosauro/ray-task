# OSS Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make ray-task installable on Linux/macOS/Windows in one command, gated by CI on every PR, released by merging a release-plz PR, and presented by a README built to be shared.

**Architecture:** Repo-level tooling only, plus one attribute in `main.rs`. lefthook runs fast local checks; GitHub Actions runs the full gate (fmt, clippy, 3-OS tests, MSRV, coverage floor, cargo-deny, PR title). release-plz (git-only mode) bumps the workspace version, writes `CHANGELOG.md` and pushes tag `vX.Y.Z`; dist (cargo-dist) reacts to the tag and publishes archives + shell/PowerShell/MSI installers to GitHub Releases.

**Tech Stack:** Rust 1.89+ workspace (`ray-core`, `ray-task`/Slint 1.18), lefthook, GitHub Actions, cargo-llvm-cov, cargo-deny, release-plz (`release-plz/action@v0.5`), dist (cargo-dist), POSIX sh.

**Spec:** `docs/superpowers/specs/2026-10-05-oss-readiness-design.md`

## Global Constraints

- Branch: `chore/oss-readiness`. Never push or open a PR without the user's explicit OK.
- Local builds on the author's machine: one cargo build at a time, always `CARGO_BUILD_JOBS=2` (the PC freezes otherwise). Never run two cargo commands in parallel.
- MSRV contract: `rust-version = "1.89"` (workspace). Do not bump it without asking the user.
- Commit messages: Conventional Commits, scopes already in use: `app`, `core`; new scopes allowed here: `ci`, `build`, `docs`, `release`. Every commit ends with the session's co-author trailer.
- Repo URL: `https://github.com/carvalhosauro/ray-task`. Binary name: `ray-task`. Packages: `ray-task` (crates/app-slint), `ray-core` (crates/core).
- No external services needing tokens other than `RELEASE_PLZ_TOKEN` (no Codecov).
- All new docs in English. App UI stays pt-BR.
- Coverage floor `N`: integer floor of measured line coverage (Task 3). Never lowered silently.
- Slint is used under its **Royalty-free license**, which requires attribution: the README must show the "Made with Slint" badge (Task 6). Do not remove it.

## Review Focus

1. **Commit messages written by git itself** (`Merge branch …`, `Revert "…"`, `fixup! …`, `squash! …`) — the commit-msg hook must let them through; a contributor doing `git revert` must not be blocked. Pinned in Task 1 tests.
2. **`install-desktop.sh` run from another directory or from a path with spaces** (e.g. `~/Downloads/ray-task v0.2/`) — must still find its icons and `.desktop` file. Pinned in Task 4 test.
3. **Pre-commit with no `.rs` files staged** (docs-only commit) — fmt check must be skipped, not fail or compile. Verified in Task 1 Step 6.
4. **Release workflows running on forks** — release-plz must not run on a fork's `main` (would fail on missing secret and spam the fork owner). Guarded with `if: github.repository_owner == 'carvalhosauro'` in Task 4.
5. **README install one-liners pointing at asset names dist actually produces** (`ray-task-installer.sh`, `ray-task-installer.ps1`, `ray-task-x86_64-pc-windows-msvc.msi`) — a wrong name means every new user's first command 404s. Cross-checked against `dist plan` output in Task 6.

- [ ] **Step 3: Write the validator**

`scripts/check-commit-msg.sh`:

```sh
#!/bin/sh
# Validates a commit message file against Conventional Commits.
# Usage: check-commit-msg.sh <path-to-commit-msg-file>
set -eu
msg_file=$1
# First line that is not a git comment.
subject=$(grep -v '^#' "$msg_file" | head -n 1 || true)

case $subject in
  "Merge "* | "Revert \""* | "fixup! "* | "squash! "*) exit 0 ;;
esac

types='feat|fix|chore|docs|refactor|test|perf|ci|build|style|revert'
if printf '%s\n' "$subject" | grep -Eq "^($types)(\([a-z0-9-]+\))?!?: [^ ].*"; then
  exit 0
fi

cat >&2 <<EOF
Commit message does not follow Conventional Commits:
  $subject
Expected: <type>(<scope>)?: <summary>   e.g. "fix(app): close tag popover on Esc"
Types: feat, fix, chore, docs, refactor, test, perf, ci, build, style, revert
EOF
exit 1
```

- [ ] **Step 4: Run test to verify it passes**

Run: `chmod +x scripts/check-commit-msg.sh && scripts/check-commit-msg.test.sh`
Expected: `all commit-msg cases pass`, exit 0.

- [ ] **Step 5: Write `lefthook.yml`**

```yaml
  commands:
    fmt:
      glob: "*.rs"
      run: cargo fmt --all -- --check

commit-msg:
  commands:
    conventional:
      run: scripts/check-commit-msg.sh {1}

pre-push:
  piped: true # stop at first failure, run in order
  commands:
    clippy:
      priority: 1
      run: cargo clippy --workspace --all-targets -- -D warnings
    test:
      priority: 2
      run: cargo test --workspace
```

- [ ] **Step 6: Install lefthook and verify each hook**

Install (prebuilt binary, no cargo build): `curl -1sLf 'https://dl.cloudsmith.io/public/evilmartians/lefthook/setup.rpm.sh' | sudo -E bash && sudo dnf install lefthook` — or download the binary from https://github.com/evilmartians/lefthook/releases into `~/.local/bin`. Ask the user before running `sudo`.

Then:
- `lefthook install` → creates `.git/hooks/{pre-commit,commit-msg,pre-push}`.
- `lefthook run pre-commit` with nothing staged → fmt is **skipped** (`(skip) no matching staged files`). Review Focus #3.
- `printf 'bad message\n' > /tmp/m && lefthook run commit-msg /tmp/m` → fails with the "does not follow" text.
- Do NOT run `lefthook run pre-push` now (full build); it runs naturally at push time.

- [ ] **Step 4: Write `packaging/install-desktop.sh`**

```sh
#!/bin/sh
# Adds ray-task to the Linux application menu (current user only).
# Run from the extracted release archive: ./install-desktop.sh
# The binary itself is installed by the shell installer or copied by you onto PATH.
set -eu
here=$(cd "$(dirname "$0")" && pwd)
dest=${XDG_DATA_HOME:-$HOME/.local/share}

# dist copies the icon dir to the archive root as ./icon; in the repo it lives under crates/.
if [ -d "$here/icon" ]; then
  icons="$here/icon"
else
  icons="$here/../crates/app-slint/assets/icon"
fi

for n in 16 32 48 64 128 256 512; do
  install -Dm644 "$icons/ray-task-$n.png" "$dest/icons/hicolor/${n}x${n}/apps/ray-task.png"
done
install -Dm644 "$here/ray-task.desktop" "$dest/applications/ray-task.desktop"

command -v update-desktop-database >/dev/null 2>&1 && update-desktop-database "$dest/applications" || true
echo "ray-task added to your application menu."
```

~~~~markdown
## The problem

Your TODO list is a few kilobytes of text. To edit it, you log in, wait for a sync, and hand a browser engine 500 MB of RAM — then pay monthly for the privilege.
ray-task keeps the list in one SQLite file on your disk and opens before you reach for the mouse.

## The numbers

Measured with **5,000 tasks** in the database:

| RAM | Switching views | Cold start (open + load) |
|:---:|:---:|:---:|
| **< 40 MB** | **< 2 ms** | **< 150 ms** |

Every number is a test you can run: [`crates/core/tests/perf.rs`](crates/core/tests/perf.rs) and the RAM procedure in [`docs/manual-checklist.md`](docs/manual-checklist.md).
~~~~
